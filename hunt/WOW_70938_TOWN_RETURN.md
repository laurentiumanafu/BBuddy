# Full-bag town return: current status

On 70938 Grind, Selling → **Use Astral Recall / Hearthstone before the vendor trip** is default-off. Off retains the existing mesh trip to a complete same-map vendor plan. On, a pending automatic full-bag or manual Sell Now trip attempts Astral Recall for a Shaman or Hearthstone for another recognized class. Select the correct class in Combat settings when Auto is ambiguous. Place the spell (ID 556) or Hearthstone item (ID 6948) directly on the first action bar (slots 1–12) using the game's default binding; macros and changed bindings are not verified. Bind the home inn within 500 horizontal yards of a complete saved vendor plan, with a town point, personally confirmed merchant and recorded sell clicks. Record a mailbox standing position for that plan if desired.

The bot stops moving, checks identity, combat, death/ghost, bar and an idle candidate, then posts one key. It monitors the experimental 70938 cast cluster and player position. A cast candidate cleared early at the origin can be retried; actual combat is handled by the existing defence path, and a previously observed active cast can be retried after combat and stable idle near the origin. Maximum three attempts. No-start, unrecognized state, absent arrival, wrong destination, changed identity or unavailable setup stops rather than blind retries. STOP remains available. World loading is held without input and bounded. A location transition is accepted only with an observed cast candidate, stable idle and changed position close to a complete recorded vendor plan; the candidate fields, class inference and location are experimental, not proof of cast or sale.

After arrival the bot uses the current map's mesh to route to the vendor. Once the vendor clicks are replayed, mailing is skipped even if a mailbox is recorded. With an active 70938 Grind profile, it chooses the nearest hotspot in the active profile area and uses the mesh to return, then resumes grinding. Interruptions for combat or unreadable state retain the return stage and do not replay selling or recall. STOP, death recovery, identity, action-bar and map guards remain active. Failed mesh or unconfirmed arrival stops instead of starting a grind somewhere else. A profile on a different map cannot be reached by the mesh alone: cross-map transport is not implemented, so the bot stops after the vendor replay. When recall is used without a profile, the bot also stops after vendor replay rather than roaming on an unexpected map; without recall the existing profile-free behavior remains. The merchant UI and actual sales are **not verified**; no mail is sent. Recording the town again clears its saved mailbox and merchant confirmations. Gather does not currently run this vendor workflow.

The user reported the first Sell Now test worked. Automatic mailing remains disabled; the saved recipient is not yet used. See `hunt/WOW_70938_MAIL_RESEARCH.md` for the requested 1–3 candidate policy, what remains unverified and a stopped read-only observation procedure. Existing 70938 automatic selling depends on experimental ordinary-bag classification and a stable zero free-slot candidate. Existing mail code is legacy and must not be assumed usable with 70938. No Lua is authorized after the earlier crashes. Do not infer success from a posted key/click, and do not blindly resend mail or sell/mail arbitrary bag slots. Windows build and live validation remain necessary.
