# 70862 external aura candidate: read-only research

The three 2026-11-08 traces showed a candidate count changing 12 → 14 when the recordings were labeled with Strength of Earth and Healing Stream, and 14 → 12 → 14 during the in/out-of-range recording. The player header candidate at `+0x5F0` pointed outside the player window, with candidate length 17 and capacity 24. This is a lead, not proof of a complete aura list, pointer semantics, effect IDs, or totem activity.

## How to record

1. Build and run the updated Windows x64 application and attach to 70862. Stop Grind, GatherBuddy, and any route; remain in a safe area. The recording does not press keys, use Lua, call game functions, or write into the client.
2. Open **Combat settings → Combat research** and check **Also record bounded external aura candidate (70862 only)**. The option starts unchecked and applies only to that recording. Keep the same character, selection and action bar throughout each trace. If the character, target, attachment, bar or bot state changes, the recorder discards the affected sample and stops.
3. Record a 25-second control with neither tested totem active. Wait until the status says **Recording**, then remain still and do nothing. Label it `no totems control`.
4. For a second trace, still with neither tested totem active, label it `Strength of Earth alone`. After **Recording** appears, wait about five seconds and manually place that totem once. Stay within range. Note its rank and the visible buff icon and approximate time. Wait for the trace to finish.
5. Once the first totem and its effect have expired or been removed, repeat with only Healing Stream, labelled `Healing Stream alone`. Note the rank and whether a player buff icon is visible. If convenient, add a fourth trace for entering and leaving range of a single totem, with approximate times and visible changes.
6. Files are saved under `Logs/CombatResearch`. They contain raw process memory, GUIDs, addresses and possibly other sensitive data; inspect before sharing. Send the traces and notes. If the trace contains `external unavailable`, send that too; it indicates an unreadable, unstable, inline or unsupported candidate, **not** an absent effect. Cancel recording with **Stop recording**.

## What is bounded

This optional diagnostic is gated to 70862 and reads no pointer graph. It double-reads the 24-byte candidate header at `player+0x5F0`, checks a plausible aligned external pointer and candidate length/capacity (maximum 24 slots, maximum capacity 32), limits the read to `length × 0x128` bytes (at most 7,104), and requires one committed readable non-guard memory region. It reads the candidate bytes twice and rechecks the header and memory region; if these change or cannot be read, the sample is unavailable and the previous baseline is discarded. Player, attachment, target and bar are checked before and after each sample. The recorder is read-only, but these checks are not atomic and cannot prevent ABA changes, pointer reuse, unrelated content or all process-read risks.

The old candidate's inline ID position is `0xE8` relative to the candidate base, with a `0x128` stride; the external representation is **not established**. The trace writes the raw bounded bytes and subsequent dword changes. `python Tools/analyze_external_aura_trace.py <trace>` reconstructs candidate triples as a research aid only. A failed read or missing candidate is not proof that an effect is absent. The optional recorder itself does not press keys or make gameplay decisions. The separately implemented 70862 totem buff feature uses this bounded read to check two observed player-effect candidates; see `TOTEM_BUFFS_70862.md`.

## Lightning Shield rank 3 (2026-11-09)

The user reported the combat recast option did not maintain Lightning Shield and supplied three traces. The action bar showed slot 6 raw `0x389` (905, Lightning Shield rank 3). The no-shield control had no candidate 905 in 100 samples. In the trace labelled active, 905 appeared at 1.25 seconds in external slot 15, with duration word 600,000 and a nonzero expiry; the count rose from 15 to 16. The third trace began with 905 present but ended after 32 samples when the selected-target state changed; **it did not capture the labelled removal/reapplication**. This supports, but does not prove, the mapping and absence semantics. The external header had length 18, capacity 24, so the prior inline 11/12-slot reader could not handle it, and the existing combat rank gate only accepted Shield 324.

The first implementation checked only 70862 action 905 in the same stable external reader/count agreement used for totems. This is a presence check, not a charge or duration reader. The combat checkbox and master buff option are still required, with a minimum 10-second per-spell attempt interval and a 125-mana estimate for rank 3 ([WoW Forever spell listing](https://warcraftforever.games/classes/shaman/spells)); actual cost/modifiers and cast success are not verified. Player, selected target, bar, combat, mana type, and candidate are rechecked; unreadable, inconsistent, duplicate or changed data is unknown and does not trigger a combat cast. The existing fresh-start quiet buff attempt and unknown 30-minute quiet fallback remain, and a valid absent candidate can prompt a quiet refresh after the usual backoff. At that point rank 1 remained on its existing inline route, and no other rank was added. Non-atomic reads and incomplete candidate semantics can still cause missed/incorrect decisions. Supervise a live combat test, including shield charges running out, and capture another stopped controlled trace if the result does not match the visible icon. This change has not been built on Windows or tested live.


## Lightning Shield ranks 1–7

The 70862 detector now supports the known seven Forever action IDs `324, 325, 905, 945, 8134, 10431, 10432`, with rank-specific estimated combat mana gates `60, 80, 125, 180, 240, 305, 370` respectively. Rank 1 keeps the previous conservative 60 estimate. Rank IDs and base costs are from [Forever spell listings](https://www.niveaumax.com/jeux/world-of-warcraft-forever/guides/sorts/chaman/10432-lightning-shield), not live 70862 cost reads; modifiers and cast success are unknown.

The detector checks for *any* known shield rank in either the valid inline candidate or the valid bounded grown candidate; a different active rank suppresses routine replacement (the existing fresh-start quiet attempt remains). When more than one eligible rank is on the bar, it chooses the highest, not all of them. Existing input, player, target, combat, mana, STOP, 10-second retry and stability guards remain. Other builds retain their prior behavior. No attempt is made to identify future unknown rank IDs or opaque macros as shields. The candidate IDs for ranks other than 1 and 3 are inferred from spell tables, not confirmed by these traces; even rank 3 disappearance was not captured in the supplied traces. The array layout, completeness, and absence/charge semantics remain experimental, and bad reads are unknown. Quiet fresh-start attempts and the existing unknown 30-minute quiet fallback are unchanged. This change has not been built on Windows or tested live.
