# Key 1 Start Attack macro (experimental 70862)

1. Stop the bot. Place a **repeat-safe, non-toggle** Start Attack macro in the first action-bar slot and ensure that slot is actually bound to `1` in your client. For example, a macro containing only `/startattack` is intended to start rather than toggle auto-attack; its behavior on this client has not been verified here. Test repeated presses manually against an appropriate target. Do not use an Attack toggle or a macro that does other unwanted actions.
2. In Combat settings → Spells, enable **Use my repeat-safe Start Attack macro on key 1 (70862)**, save, then start the bot. The option defaults off. Slot 1 is reserved and excluded from spell, buff, heal, food and drink selection in this mode. Avoid overriding the key binding while running.
3. The bot attempts `1` once at the start of each fight (including at range) and after each in-combat heal or Earth, Frost or Flame Shock attempt, provided its safety checks still pass. After a heal it waits through the 3.6-second heal verification window; this is not proof that the cast completed or succeeded. If the target dies, changes, becomes unsafe, or STOP is requested, the follow-up is withheld. The existing 70862 defence heuristic may choose the wrong NPC, as previously acknowledged.
4. The macro option takes priority over the separate F6–F10 post-heal Start Attack option and disables the normal Attack/right-click combat inputs. On a Shock-only Shaman the bot still closes to melee while the estimated Shock cooldown is active. It cannot verify macro contents, binding, cast success, or swing state. The nonempty slot check only verifies a candidate action-bar value, not that it is a macro. The action-bar/session guard can hold the bot if the bar changes or becomes unreadable.

The option applies only to build 70862. Changing it requires stopping the bot. This has not been tested in the game or built on Windows.
